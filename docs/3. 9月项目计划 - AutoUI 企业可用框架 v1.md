# 2026 年 9 月项目计划 - AutoUI 企业可用框架 v1

> [!summary] 项目目标
> 在 9 月完成一套可重复执行、可并行、可诊断、可接入 CI 的 Web UI 自动化框架 v1。
>
> 项目不追求目录和抽象数量，而以真实回归流程、稳定生命周期、失败诊断和 CI 门禁作为完成标准。

---

## 项目背景与基线

AutoUI 当前已具备 pytest-playwright、基础 Page Object、YAML 参数化、Context 配置和失败截图/trace 等基础能力。

本项目以现有代表流程作为回归安全网，在保留 Playwright 原生 Locator、auto-waiting 和 `expect()` 的前提下完成框架重构。

---

## 项目范围

### 本月交付

```text
模块化 pytest 框架骨架。
配置优先级、启动校验与 secrets 边界。
独立 BrowserContext、运行身份和并行隔离。
结构化日志、失败截图、页面源码和 trace。
JUnit XML、Allure results 与 GitHub Actions 门禁。
串行、xdist -n 2、受控失败和 CI 验收记录。
```

### 本月不做

```text
不接入 Appium、移动端和 PC 自动化实现。
不创建 CommonDriver、BaseTestCase、Locator 包装层或二次等待层。
不建设测试平台、设备农场、账号池和复杂重试机制。
不为了未来多端预先创建 app/、pc/ 或空的抽象接口。
```

## 工程设计原则

### 真实需求驱动的文件与抽象

```text
不按“一个概念一个文件”拆分代码。

新增 .py 文件必须满足至少一项：
1. 它有独立职责，且与现有文件的依赖不同。
2. 它被两个或以上真实调用方复用。
3. 留在当前文件会导致 pytest、Playwright、配置或运行时职责明显混杂。

不因未来可能性创建空模块、空目录、空基类或空 Protocol。
当真实调用方出现后，再提炼 Component、Flow、runtime、evidence 等模块。
```

当前配置阶段只保留：

```text
autoui/core/config/settings.py
  配置读取、优先级解析、校验、Settings 构造。

autoui/plugins/configuration.py
  pytest CLI 参数、session 初始化和 settings fixture。
```

### 多端演进边界

```text
当前仅实现 Web。

未来 App / PC 可共享配置、运行身份、日志、证据和报告契约；
不提前统一 click、fill、Locator、等待、断言或 Driver。

只有多个平台出现经过验证的共同需求时，才提炼跨端契约。
```

### 依赖方向

```text
tests -> Web Pages / Flows -> pytest fixtures -> pytest-playwright
pytest plugins -> core config / runtime
core 不依赖 pytest、Playwright 或具体平台实现
```

## 阶段 1：模块骨架、配置与生命周期

目标：

```text
完成清晰的 Web 框架包结构。
实现 CLI > 环境变量 > profile > 默认值 的配置优先级。
将账号、密码、token 限制为环境变量或 GitHub Secrets。
在 Browser 启动前校验必填配置。
保留一个可串行执行的代表回归流程。
```

验收：

```text
pytest --collect-only -q --strict-markers 成功。
缺少必填配置时，在 Browser 启动前清晰失败。
配置完整时，代表流程串行通过。
仓库、日志和输出中不出现明文 secrets。
```

---

## 阶段 2：BrowserContext、数据、产物隔离与并行

目标：

```text
每个 pytest item 使用独立 BrowserContext。
建立 testrun_uid、worker_id 和 test identity。
为可变数据和 artifact 设计唯一命名与隔离路径。
使用 pytest-xdist -n 2 证明至少两个 worker 实际执行测试。
```

验收：

```text
串行与 -n 2 的结果一致。
不同测试不覆盖数据、日志、截图或 trace。
连续执行不读取上次残留状态。
```

---

## 阶段 3：失败证据、报告与 CI

目标：

```text
统一关联日志、截图、页面源码、trace 与 pytest report。
生成 JUnit XML 与 Allure results。
建立 GitHub Actions，在干净环境安装依赖、浏览器并执行并行回归。
失败时仍上传证据，但不掩盖测试失败退出码。
```

验收：

```text
CI 收集错误、未知 marker、安装失败和回归失败都会失败。
失败后可按 test identity 找到完整证据。
JUnit、Allure results 与 CI artifacts 可下载和查看。
```

## 月度完成标准

```text
代表回归流程可稳定串行运行。
xdist -n 2 实际由两个 worker 执行，且结果一致。
测试具备独立 Context、数据和 artifact。
配置有明确优先级，secrets 不进入仓库与报告。
失败后可定位日志、截图、页面源码和 trace。
GitHub Actions 能阻止不合格变更。
```

### 当前设计约束

- 不再为了“企业框架”预先创建大量空 Python 文件。
- 当前配置实现只保留两层：
  - `autoui/core/config/settings.py`：YAML、环境变量、配置解析、Settings 构建与校验；不依赖 pytest。
  - `autoui/plugins/options.py`：pytest CLI 参数、session hook、settings fixture；不再新增 `configuration.py`。
- `web.py` 只消费 `settings` fixture，不自行读取 YAML、环境变量或 CLI。
- secrets 不进入 YAML、Settings、日志或报告。
